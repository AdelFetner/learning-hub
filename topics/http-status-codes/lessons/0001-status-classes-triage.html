Lesson 0001 · HTTP Status-Code Classes

The first digit tells you whose side to debug

One triage rule, five classes, three confusable pairs. ~7 minutes.

The one idea

Every HTTP response carries a three-digit status code, and the classes are defined purely by the first digit (RFC 9110 §15). When a request fails at work, you don't need the exact code first — the class alone tells you where to look:

RangeClass (per MDN)Your debugging move
1xxInformationalInterim, not an outcome — you'll rarely meet one in logs.
2xxSuccessThe request worked. Bug still there? It's in the payload or your handling of it.
3xxRedirectionThe answer is elsewhere — follow the Location header.
4xxClient errorInspect the request: URL, method, headers, auth, body.
5xxServer errorInspect the server: its logs, or the upstream it calls.
Memory hook: 4 = you, 5 = them. A 4xx says the caller sent something the server can't or won't process; a 5xx says the caller did fine and the server fell over anyway.

The three pairs people mix up

401 vs 403 — 401 Unauthorized really means unauthenticated: "who are you?" — credentials are missing or invalid. 403 Forbidden means "I know exactly who you are, and you're not allowed." Fixing a 401 means logging in correctly; fixing a 403 means changing permissions.

502 vs 504 — both come from a proxy/gateway blaming the server behind it. 502 Bad Gateway: the upstream answered, badly (invalid response). 504 Gateway Timeout: the upstream never answered in time. 502 → look for upstream crashes; 504 → look for slowness, deadlocks, network.

301 vs 302 — 301 Moved Permanently: the new URL is forever, and clients/caches may remember it aggressively. 302 Found: it's elsewhere for now; keep using the original URL next time.

Retrieval practice

Answer from memory — the table above earned its keep only if you can do this without scrolling up.

1. Your service log shows a request that ended in 503. Whose side do you investigate first?

5xx = server class: the server is alive but can't serve right now (overload or maintenance). The request was fine.

2. An integration you call starts returning 422. You've never seen that code. Which class — and so, whose bug?

First digit 4 → client error class → inspect the request you sent, even if you've never met the specific code.

3. The token is valid and the user is logged in, but they may not access this resource. Which code fits?

403 Forbidden = authenticated but not allowed. 401 would mean the credentials themselves are missing or invalid.

4. The reverse proxy waited and waited; the app behind it never responded. Which code does the proxy return?

504 Gateway Timeout = upstream never answered in time. 502 would mean it answered with an invalid response.

5. A 302 means the resource has moved how?

302 Found = temporary — keep using the original URL. Permanent moves are 301, which caches may remember forever.
