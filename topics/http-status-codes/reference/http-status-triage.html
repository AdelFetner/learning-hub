HTTP Status Triage

The first digit tells you whose side to debug.

The five classes

RangeClassDebugging move
1xxInformationalInterim response — rarely seen in logs; not an outcome.
2xxSuccessRequest succeeded. If behaviour is still wrong, the bug is in the payload or your handling of it.
3xxRedirectionFollow the Location header; check the client follows redirects.
4xxClient errorInspect the request — URL, method, headers, auth, body.
5xxServer errorInspect the server — its logs, or the upstream it depends on.

Codes you'll actually meet

CodeNameMeans
200OKSucceeded; meaning depends on the method.
201CreatedSucceeded and a new resource now exists.
301Moved PermanentlyNew URL forever — clients/caches may remember it.
302FoundElsewhere for now — keep using the old URL.
401UnauthorizedNot authenticated — "who are you?" Send (valid) credentials.
403ForbiddenAuthenticated but not allowed — "I know you; you can't."
404Not FoundNo resource at this URL (or the server hides it).
429Too Many RequestsRate limited — slow down, honor Retry-After.
500Internal Server ErrorThe server itself crashed handling the request.
502Bad GatewayThe proxy's upstream answered with garbage.
503Service UnavailableServer alive but can't serve — overloaded or in maintenance.
504Gateway TimeoutThe proxy's upstream never answered in time.

Confusable pairs

401 vs 403401 = authentication missing/invalid. 403 = authenticated, permission denied.
502 vs 504502 = upstream replied badly. 504 = upstream didn't reply in time.
301 vs 302301 = moved forever (cacheable). 302 = moved temporarily.
